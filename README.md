# 第一部分 · 实践与应用

## 1. Hermes 是什么（30 秒版）

Hermes Agent 是 Nous Research 开源的 AI 智能体框架（[nousresearch.com](https://hermes-agent.nousresearch.com)）。和"IDE 里的补全助手"不同，它能**自己动手直到任务完成**：

| 能力 | 一句话说明 |
|---|---|
| 终端与代码执行 | 自己跑命令、写脚本、查日志，直到验证通过 |
| 浏览器自动化 | 驱动无头 Chrome 打开测试环境、点击、取数、截图验证 |
| MCP 工具接入 | 插件直连禅道、GitLab、数据库、邮件等内部系统 |
| 持久记忆 | 记住你的环境、偏好、踩过的坑，跨会话不重复教 |
| Skills 技能库 | 把验证过的工作流沉淀成可复用的"操作手册" |
| 定时任务 (cron) | 巡检、监控、报告按计划自动触发 |

**为什么选它做 QA 工作**：缺陷验证和性能回归这两类任务重复、琐碎但要求严谨——正好是智能体的甜点区。

## 2. 案例一：禅道 Bug 修复的自动化验证

**痛点**：开发把 bug 标为 resolved 后，测试要手动登录、按复现步骤逐项点击核对。一个后台配置类 bug 走完要 15~20 分钟，还容易漏检查点。

**做法**：接入禅道 MCP，形成自然语言触发的流水线：

```
你：验证这个 bug → https://chandao.k0v.cn/zentao/bug-view-38535.html

Hermes 自动完成：
  ① MCP 拉取 bug 详情（复现步骤 / 实际结果 / 期望结果）
  ② 无头 Chrome 登录测试环境 fawdemo-admin.y8e.net
  ③ 把"期望结果"拆成检查点，逐项在真实页面验证
  ④ 输出中文验证报告（检查点 × 期望 × 实际 × 通过/失败）
  ⑤ 给出禅道操作建议（关闭 / 打回）——决策留给人
```

**实测战果（2026-09-01，Bug #38535【后台】关注链接内容需优化）—— 一次完整的"两轮验证"**：

- **13:38 初验**：开发尚未处理，Hermes 跑完测试环境后给出 **5 项检查点全部 ❌** 的报告——"社交链接仍存在、字段未改名、统计代码未迁移"，并主动与禅道状态交叉核对：*「与禅道 bug 状态 active 一致，待开发处理后可再次验证」*。**它没有为了让报告好看而放水，该判不通过就判不通过。**
- **13:39 开发修复**（禅道状态转为 resolved/fixed）。
- **13:4x 复验**：我只说了一句 **"verify again"**，它重跑验证脚本（无头 Chrome 登录 → 抓取两个配置页全部字段 → 逐项判定），输出复验报告：

| 检查点 | 期望 | 实际 | 状态 |
|---|---|---|---|
| 微博/微信等社交链接配置项 | 全部去除 | 已不存在 | ✅ |
| 「第三方统计代码」改名 | 「统计代码」 | 旧名消失、新名存在 | ✅ |
| 「统计代码」迁移至站点配置 | /manage/config/site/ | 含该字段 | ✅ |
| 旧入口 /manage/config/link/ | 不再单独维护 | 自动跳转并入站点配置 | ✅ |

**结论：✅ 5/5 通过，建议禅道关闭该 bug。** 全程我只输了两句话。

## 3. 案例二：后台系统性能优化验证（数据说话）

**背景**：核心后台页面响应时间目标 ≤ 1 秒，开发优化后需要一轮可复现的回归测量。

**做法**：Hermes 编写 Playwright 性能测试脚本（无头浏览器 + 复用登录态），逐页测量、出对比表、给分级建议。

**实测数据（2026-08-31，优化前后对比）**：

| 页面 | 优化前 | 优化后 | 改善幅度 | 达标(≤1s) |
|---|---|---|---|---|
| 用户报表 | 2035 ms | 936 ms | **−54%** | ✅ |
| 接包报表 | 2004 ms | 954 ms | **−52.4%** | ✅ |
| 搜索列表 | 1743 ms | 1365 ms | −21.7% | ⚠️ 待优化 |
| 竞标项目 | 1543 ms | 1182 ms | −23.4% | ⚠️ 接近 |

**决策价值**：2 个已修复项不再重复建单；剩余 2 项从 P1 降为 P2——优先级基于实测而非估计；下一轮优化有了量化基线。

## 4. 案例三：把经验沉淀成 Skill + 真实排障

- **工作流固化**：第一轮验证踩过环境坑（pip SSL 问题需换 uv、无头浏览器等待策略、NodeList 遍历陷阱）。走通后整条流程被固化为 `chandao-bug-verify` 技能——之后贴一个链接说"验证这个 bug"即可端到端执行。**同类任务第 N 次的成本远低于第 1 次**，这是 Hermes 与"每次从零聊"的对话框产品的本质差别。
- **一次真实排障**：桌面端报"WebSocket session token 拒绝"，Hermes 顺日志找到根因——后端源码混入一段残留的 `=======` diff 标记导致启动崩溃——自行修复、重编译字节码、验证恢复。
- **角色库接入**：把 agency-agents-zh 的 276 个中文 AI 专家角色（技术文档工程师、安全工程师、产品经理等 20 个部门）一键转换成 Hermes 技能——**本报告正是用其中的"技术文档工程师"角色起草的**。

## 5. 案例四：一句话上线一个内容监控（cron）

**需求**（2026-09-02 14:39）：只说了一句"这个 AI 新闻站 https://ai.xphub.dev/ 有更新就通知我"。

**Hermes 自动完成**：
1. 先探路：首页是 JS 应用，直接抓取只能拿到"正在加载…"——**它没有硬抓，转而找到站点背后的 RSS 数据源**；
2. 创建 cron 任务「AI Pulse 新品监控」：每 15 分钟检查一次 feed，有新文章才启动 AI 生成中文摘要推送给我，无更新则完全静默；
3. 我 15:44 问了句"检查下是否正常"，它拉出完整运行记录核对：

| 时间 | 状态 | 行为 |
|---|---|---|
| 14:47 | 手动触发 | 建立基线，推送首份报告 |
| 15:02 | 调度首 tick | 正式基线，报告已投递 |
| 15:18 | `no_change` | 变更检测拦截 → **静默跳过，零 LLM 开销** ✅ |
| 15:33 | `no_change` | 同上 ✅ |

**关键设计**：便宜的"探测-变更检测"层每 15 分钟跑一次（纯脚本，不花钱），只有 feed 真变了才唤醒模型写摘要——**监控成本几乎为零，而且从建立到验证全程不到一小时**。这套模式下一步就能原样搬到性能巡检、禅道待验证 bug 盯梢上。

# 第二部分 · 使用技巧分享

## 技巧 1：辅助模型配置 —— 小任务用小模型，省钱提速

Hermes 主模型之外还有一组"辅助任务"：上下文压缩摘要、图片识别、标题生成等。这些任务高频但不难，没必要都用最贵的模型。

```yaml
# ~/.hermes/config.yaml
auxiliary:
  compression:
    provider: custom:icgnewapi.k0v.cn
    model: qwen3.8-flash      # 长会话压缩摘要 → 轻量模型
  vision:
    provider: custom:icgnewapi.k0v.cn
    model: qwen3.8-flash      # 截图/图片分析 → 轻量模型
```

改完让 Hermes **实测验证路由生效**（它会直接调用一次确认返回），不是"配置了就算完了"。我的主模型只留给核心推理，长会话成本明显下降。

## 技巧 2：记忆持久化 —— 只教一遍

Hermes 有跨会话的持久记忆（`~/.hermes/memories/`），会注入每一次新会话。我让它记住的事实例如：

> - "本机 pip 有 SSL 问题，装 Python 包用 uv"
> - "测试环境是 fawdemo-admin.y8e.net，用无头 Chrome，别动我的浏览器"
> - "汇报和报告用中文"

**用法心得**：说出偏好或纠正它时，加一句"记住这个"；它也会主动沉淀。环境事实、路径、账号约定这类"每轮都要重说"的信息进记忆；可复用的操作流程进 Skill——两者分工不同。

## 技巧 3：多人格 —— 一个代理，按需切换专家角色

配合刚装的 276 个角色库，同一个 Hermes 实例可以扮演不同专家：写文档时加载"技术文档工程师"，审代码时切"安全工程师"，做选型评估用"工具评测专家"。每个角色有自己的身份、工作方法和交付标准，本质上是**结构化的系统提示词 + 专业流程**。

三种落地方式：
1. **自然语言**："以小红书运营专家的角色分析这篇笔记"（自动匹配技能）
2. **手动点名**：`skill_view` 加载指定角色后再布置任务
3. **子代理并行**：`delegate_task` 同时派多个角色，各干各的再汇总

**避坑**：角色库全量 276 个别往 Discord 里装（斜杠命令 8000 字符上限会炸），按 `--category` 分批；桌面/CLI 端无限制。

## 技巧 4：MCP 接入内部系统 —— stdio 模式零运维

禅道、GitLab 的 MCP 服务器都走 **stdio 管道**（不是网络服务）：不占端口、不用配防火墙、客户端退出进程自动结束。同一份配置我已复制到同事的 Windows 机器，`cmd /c` 拉起即用。

## 技巧 5：验证文化 —— 不信"说做完了"，要看证据

Hermes 的硬约束：外部写操作必须读回验证（"报告已更新"≠更新成功），数字统计必须程序化核对。这条既是它的行为准则，也是我使用它的纪律——**AI 出证据，人做决定**，关 bug、提代码的最后一键始终在测试手里。

**现场小例子（改测试环境 favicon）**：我让 Hermes 把 `~/Pictures/prod_favicon.ico` 从绿色改成红色，用于区分测试环境站点标签页。它的执行链恰好展示了什么叫"闭环验证"：

1. 先 `file` + numpy 摸清图标结构（32×32 单帧、绿色系像素分布）；
2. 在 HSV 空间按色相区间（54°~216°）定位 608 个绿色像素，保留饱和度/亮度转红——边缘抗锯齿不糊；
3. 覆盖前先备份 `.bak`；
4. 改完想"亲眼看"：`vision_analyze` 直接读 .ico 失败（不认识该格式）→ **自己换路**：转成 PNG 预览再视觉复核，确认"深红圆盘、零残留绿色"；
5. 最后程序化统计验证：1024 个不透明像素中绿色残留 = 0，并确认仍是单帧 32×32 结构。

第 4 步是重点：工具失败它不吭一声放弃，而是换路径把"亲眼确认"补上。这种"执行 → 失败 → 自适应 → 读回验证"的闭环，就是智能体和聊天框的区别。

# 第三部分 · 我用 AI 做出来的工具与网站

> 以下全部为 AI 结对产出：我提需求和验收，AI 写代码调试。类型覆盖 Chrome 插件 ×4、工具站 ×1、桌面程序 ×1。

## 1. cURL → 本地调试（Chrome/Edge 插件）

**解决什么**：排查接口问题时，从 DevTools 复制的 cURL 指向远程测试域名，手动改地址、加 Host 头繁琐易错。

**做什么**：复制 DevTools「Copy as cURL」后一键转换为本地 `127.0.0.1:8000` 请求并**保留原 Host 头**（适配本地 nginx 反代路由），弹窗直接展示响应结果。三种触发：扩展弹窗、快捷键 `Ctrl+Shift+U`、右键选中文本。域名映射、端口、自动发送均可配置。

**亮点**：已按 Chrome 商店审核要求去掉了 `<all_urls>` 宽权限，准备了隐私政策页和 GitHub Pages 发布——是从"自用脚本"到"可发布产品"的完整度。

## 2. 方案网小工具（Chrome 插件，v0.1.10）

**解决什么**：测试方案网（faw2026.y8e.net）时反复登出登入切账号、查数据库配置全靠手。

**做什么**：查看当前账号 + 店铺信息（账号/昵称/会员等级/店铺状态等），**一键切换任意账号**（顶部保留最近 7 个快速切回）；内置查询数据库、Redis 缓存、全局配置——后端查询服务部署在内网 `192.168.0.177:18766`，**同事局网内加载插件即用，不用自己起后端**。

**亮点**：这是团队共享的工具，README 专为同事写了"不用自己启动后端"的上手路径。

![方案网小工具：账号概览 + 多账号切换 + 数据库/缓存/配置快捷查询](https://test-fawoss2026.oss-cn-shenzhen.aliyuncs.com/attachment/area-capture/20260902-152324-rjkv9r.png)

## 3. 网络响应关键字搜索（Chrome 插件，v1.0.0）

**解决什么**：想知道"哪个接口返回了这句话/这个字段"，在 DevTools Network 里一个个点开找效率极低。

**做什么**：自动抓取当前页面的所有网络请求，在侧边栏**按响应体内容做关键字搜索**，直接定位返回目标内容的请求。

## 4. Skip Debugger（Chrome 插件）

**解决什么**：部分外部站点（如社保/招聘类 gdjy.net、ic.net.cn）用 `debugger` 语句反调试，F12 一开就卡在断点上没法分析。

**做什么**：多层拦截——`window.Function`、`function(){}.constructor`、`eval` 中的 debugger，过滤定时器回调兜底，再用 Chrome Debugger API 自动 `setSkipAllPauses`。**按域名白名单生效**，白名单外的站点（如我们自己的测试环境）完全不受影响；保存白名单后动态注册脚本，不用改代码。

## 5. HuTu 工具箱（本地工具站）

**是什么**：Hu = 胡，Tu = Tool。本地跑的个人工具箱（Python 3.10+，零外部依赖），**不用翻墙访问国外工具站**，数据不出本机。

**功能**：工具首页分类导航 + 卡片（全部/数据格式/文本工具/开发工具/icgoo工具）；Dict to JSON（Python 字典转 JSON）、JSON Viewer、时间戳转换、URL 编解码、文本格式转换、在线记事本、Markdown Reviewer、在线代码编辑器、白板、图片 OCR（本地 RapidOCR / 云端 GLM-4V）、Request Local（线上 curl 转本地请求，带端口映射与发送历史，即插件 #1 的网页版）、Posthuman（类 Postman）、一键请求查看、清查缓存等 **14+ 个小工具**，仍在持续扩充。带**管理后台**可视化配置工具卡片（Logo/简介/跳转/分类），`tools.json` 注册即可扩展新工具——已经是个小平台架构。

![HuTu 工具箱首页](https://test-fawoss2026.oss-cn-shenzhen.aliyuncs.com/attachment/area-capture/20260902-154027-5a0bcq.png)

## 6. Area Capture（Linux 桌面截图程序，Electron）

**解决什么**：Linux 下缺少一个"截图后直接传 OSS 拿链接贴工单"趁手工具（禅道/邮件插图都需要）。

**做什么**：常驻系统托盘的框选截图工具，截图后在选区旁面板一键完成：
- **复制到剪贴板** / **保存 PNG 到本地** / **上传阿里云 OSS**（自定义 bucket、前缀、超时）
- **OCR**（RapidOCR / PP-OCRv4，与 HuTu 同源方案）
- **贴图钉屏**：截完钉在最上层，可拖动、滚轮缩放、右键再复制/保存
- **标注**：箭头、直线、矩形、椭圆、画笔、文字、**步骤序号**、马赛克模糊；Ctrl+Z 撤销
- 全套快捷键：`Ctrl+Shift+Alt+O/C/F/S` 对应 OCR/复制/存图/传 OSS，免进面板

**实际产出**：本报告引用的截图（如方案网小工具的产品图）就是它直接传 OSS 生成的链接——工具之间已经形成闭环。

## 7. 这些工具是怎么被"AI 造"出来的

一条典型路径（以 Area Capture 为例）：

```
一句话需求 → AI 出技术方案（Electron + RapidOCR + OSS SDK）
  → 搭骨架、写核心模块 → 我试用提反馈（"贴图要能拖出屏幕边缘"）
  → AI 定位修复 → 沉淀 README/快捷键表 → 日常使用中持续迭代
```

体会：**AI 把"想做个小工具"的门槛从"会不会写这个栈"降到了"提不提得清需求"**。上面 6 个工具全部诞生于近几个月，涵盖 Chrome MV3、Electron、Python 服务三种技术栈——放在以前，光选型和踩坑就劝退了。

## 踩坑心得

1. **智能体 ≠ 聊天机器人**：价值在"执行-验证"闭环，它自己确认跑通了才算完。
2. **先划权限边界再放手**：涉及生产数据的操作保持"它验证、我拍板"。
3. **环境坑第一时间固化**：写进 Skill/Memory，否则每轮会话重踩一遍。
4. **数字必须可溯源**：报告里每个数据都来自真实执行输出，这是团队敢采纳结论的前提。
